# 오늘머니 — 오늘의 증시 브리핑

하루 두 번, 각 시장이 문을 닫은 직후에 보유 종목의 가격과 뉴스를 모아 브리핑을 만들고,
피그마 시안에서 뽑아낸 프로토타입에 그대로 꽂는다.

**배포:** https://oneulmoney.vercel.app

| 시각 (KST) | 대상 | 무엇을 담나 |
| --- | --- | --- |
| 오전 7:00 | `--market us` | 밤사이 끝난 미국 증시 마감 + 해외 종목 뉴스 |
| 오후 4:30 | `--market kr` | 그날 끝난 한국 증시 마감 + 국내 종목 뉴스 |

여기에 더해 국내 장중에는 `--market kr --slots-only`가 세 번 더 돈다. 마감 브리핑은
건드리지 않고 Portfolios 탭의 시간대별 슬롯만 채운다 → [장중 갱신](#장중-갱신)

```
보유 종목 (data/portfolio.json)
      ↓
가격    pykrx(국내) · yfinance(해외)
장중    yfinance 5분봉 → 정해진 시각의 시세 (Portfolios 탭 전용)
뉴스    Google News RSS · yfinance Ticker.news
문구    Claude API — 번역 · 카드 요약 · 시간대별 브리핑
      ↓
briefings/YYYY-MM-DD-{us,kr}.md   ← 사람이 읽는 브리핑 (가격표·뉴스 원문·링크)
data/briefing.js                  ← 프로토타입이 읽는 데이터
      ↓
index.html + styles.css + app.js
```

**각 실행은 자기 시장만 갱신하고 반대편은 직전 것을 그대로 남긴다.** 프로토타입의
시장 전환 버튼(요약 타이틀 탭)이 양쪽 다 살아 있어야 하기 때문이다. 그래서 아침 7시
실행 뒤에도 어젯밤 한국 브리핑을 계속 넘겨볼 수 있다.

## 자동 실행

**GitHub Actions**가 돌린다 (`.github/workflows/briefing.yml`).
결과를 저장소에 커밋하면 Vercel이 감지해 자동 재배포한다. 맥이 꺼져 있어도 돌아간다.

```
마감 브리핑 — 홈 탭 + 포트폴리오 탭 전체
  22:00 UTC = 07:00 KST → --market us
  07:30 UTC = 16:30 KST → --market kr

장중 갱신 — 포트폴리오 탭 슬롯만 (평일)
  00:20 UTC = 09:20 KST → --market kr --slots-only
  01:40 UTC = 10:40 KST → --market kr --slots-only
  04:10 UTC = 13:10 KST → --market kr --slots-only
```

- **API 키**는 저장소 Settings → Secrets and variables → Actions 의 `ANTHROPIC_API_KEY`
- Actions 탭에서 **Run workflow**로 즉시 실행할 수 있다 (슬롯만 갱신하는 체크박스도 있다)
- cron은 정시를 보장하지 않는다. **실측으로 1~2시간 반까지 밀린다.**
  위 시각은 "이보다 이르지는 않다"는 뜻으로 읽어야 한다

로컬 launchd 스케줄은 Actions로 옮기면서 해제했다. 되돌리려면
`~/Library/LaunchAgents/disabled-notefolio/`의 plist를 원래 자리로 옮기고 `bootstrap` 한다.

### 장중 갱신

국내 슬롯은 9:10 / 10:30 / 1:00 / 마감 네 개인데, 마감 실행 한 번으로는 저녁까지
포트폴리오 탭이 전 거래일에 머문다. 그래서 장중에도 세 번 돌려 지나간 시점을 채운다.

**`--slots-only`는 마감 브리핑을 건드리지 않는다.** 홈 탭은 하루 두 번 마감 브리핑만
쓰기로 돼 있어서(`config.INTRADAY_ENABLED` 옆 설명), 장중 실행이 카드 제목·본문·헤드라인
까지 덮어쓰면 오전 10시에 "한국 증시 요약 10:40AM"이 마감 요약 자리에 앉는다.
`emit._merge_slots`가 직전 산출물의 카드에서 `slots`만 갈아끼우고 나머지는 그대로 둔다.
`refreshed`에도 넣지 않는다 — 그 목록이 `default` 시장을 정하는데, 슬롯 갱신 때문에
홈 탭이 국내로 뒤집히면 안 된다.

같은 이유로 마크다운 브리핑도 쓰지 않는다. 반쪽짜리 하루로 그날 문서를 덮어쓰면
저녁 마감 실행 전까지 남는 기록이 장중 스냅샷이 된다.

**실행이 밀리거나 하나 걸러 실패해도 된다.** 각 실행이 그날 5분봉을 통째로 받아
지나간 시점을 처음부터 다시 다 뽑기 때문에, 다음 실행이 빠진 슬롯을 알아서 메운다.
아직 오지 않은 시각은 빠진 채로 나오고, 진행 바는 있는 슬롯 수가 아니라 그 시장의
하루 슬롯 수(`slot_total`, 국내 4)로 나눠서 3/4까지만 찬다.

## 직접 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -r pipeline/requirements.txt
bash pipeline/setup_key.sh                      # API 키 저장 (~/.config/notefolio/env)

.venv/bin/python pipeline/run_daily.py --market us    # 미국만
.venv/bin/python pipeline/run_daily.py --market kr    # 한국만
.venv/bin/python pipeline/run_daily.py --market all   # 둘 다
.venv/bin/python pipeline/run_daily.py                # auto — 정오 전이면 us, 후면 kr

# 장중 — 마감 브리핑은 그대로 두고 시간대별 슬롯만 갱신
.venv/bin/python pipeline/run_daily.py --market kr --slots-only
```

`--summarizer rule`을 붙이면 API를 쓰지 않고 규칙 기반(헤드라인 나열)으로만 만든다.

프로토타입을 로컬에서 보려면 서버가 필요하다. `data/briefing.js`를 `<script src>`로
읽기 때문에 `file://`로 열면 브라우저가 막고, 그때는 `app.js` 안의 예시 데이터로 떨어진다.

```bash
python3 -m http.server 4173
```

## 보유 종목 바꾸기

`data/portfolio.json`의 `holdings`만 고치면 된다.

```json
{ "market": "KR", "ticker": "000660", "name": "SK하이닉스" }
{ "market": "US", "ticker": "MSFT", "name": "마이크로소프트", "en_name": "Microsoft" }
```

- `market` — `"KR"`이면 pykrx, 그 외에는 yfinance
- `ticker` — 국내는 6자리 종목코드, 해외는 야후 심볼
- `name` — 화면 표기 + 뉴스 검색어
- `en_name` — 해외만. 영문 기사가 이 종목 것인지 걸러내는 데 쓴다

## 토스증권 연동 (예정)

`pipeline/brokers/toss.py`의 `fetch_holdings()`만 채우면 된다. `sync()`가 그 결과로
`data/portfolio.json`을 덮어쓰고 나머지 코드는 그대로 둔다.
자격증명은 `TOSS_APP_KEY` / `TOSS_APP_SECRET` / `TOSS_ACCOUNT_NO` 환경변수로 받는다.

## 알아둘 것

**시간대를 시장에 맞춰 나눈 이유.** 오전 7시에는 국내 장이 열리기 전이라 국내 시세가
전 거래일 종가고 뉴스도 7시간치뿐이다. 오후 6시에는 미국 장이 시작도 안 했다.
그래서 각 슬롯이 방금 마감한 시장만 맡는다. 어느 거래일 종가인지는 마크다운의
`기준 거래일` 칸과 `briefing.json`의 `as_of`에 남는다.

**오전 7시는 미국 마감 뒤로 안전하게 떨어져 있다.** 미국 장 마감(현지 16:00)이
서머타임 기간엔 KST 05:00, 표준시 기간엔 KST 06:00이라 어느 계절에도 일봉이 확정된
뒤에 돈다. 6시로 당기면 겨울에 마감과 겹쳐 전일 종가가 잡힐 수 있다.
같은 이유로 미국은 더 당길 수 없다.

**국내는 18:00에서 16:30으로 당겼다.** 장 마감이 15:30인데 18:00은 두 시간 반을
놀리고 있었다. 브리핑 완성 뒤에 카카오톡 알림(아래)을 저녁 시간에 받으려고 당겼다.
대가는 마감 후 뉴스를 한 시간 반 덜 모으는 것이다 — 카드 문구의 근거가 그만큼 얇아진다.

**카카오톡 알림은 저장소 밖에 있다.** claude.ai의 클라우드 루틴 두 개가 배포된
`data/briefing.js`를 받아 `refreshed_at`이 오늘인지 확인하고, 오늘일 때만 알림을 보낸다.
파이프라인은 이 존재를 모르고, 알림 쪽도 저장소를 건드리지 않는다.
루틴 관리: https://claude.ai/code/routines

| 알림 | 발송(KST) | 조건 |
| --- | --- | --- |
| 미국 | 화~토 09:00 | `markets.us.refreshed_at`이 오늘 |
| 국내 | 월~금 18:00 | `markets.kr.refreshed_at`이 오늘 |

GitHub Actions cron이 밀리면 브리핑이 발송 시각보다 늦게 도착할 수 있다. 그때는
알림을 보내지 않고 건너뛴다 — 틀린 알림을 보내느니 거르는 편이 낫다.

**시간대별 브리핑은 마감 후에 한 번에 만든다.** 장중에 여러 번 돌 필요 없이 그날
5분봉을 통째로 받아 정해진 시각만 뽑아낸다.

| 시장 | 슬롯 |
| --- | --- |
| 국내 | 9:10AM · 10:30AM · 1:00PM · 마감 |
| 해외 | 11:00PM · 마감 (KST — 한밤중이라 중간 시점을 여러 개 둬도 볼 사람이 없다) |

시각은 `config.INTRADAY_TIMES_KR` / `INTRADAY_TIMES_US`에서 고친다. 30분봉으로는
9:10을 집을 수 없어서 5분봉을 쓰고, 값은 그 봉의 **시가**를 쓴다 — 종가는 5분 뒤
가격이라 '9:10의 주가'로 내걸기에 맞지 않는다.

마지막 슬롯은 공식 종가로 덮어쓴다. yfinance의 장중 마지막 봉이 거래소 종가와
어긋나서(국내는 15:30 마감인데 14:30 봉이 마지막인 경우가 있다) 그대로 두면 같은
화면에서 카드와 슬롯 가격이 달라진다.

**슬롯은 언제나 장이 끝난 거래일에서 뽑는다.** 손으로 장중에 돌리면 오늘 봉이 반쪽만
있어서 9:10과 10:30만 나오고 1:00PM·마감이 빈다. 그런 날은 건너뛰고 직전 거래일을
쓴다. 그러면 슬롯의 거래일이 카드 시세(오늘)와 달라지므로, 등락률 기준선을 그 날의
전 거래일 종가로 다시 잡고 슬롯마다 `date`를 실어 보내 화면이 맞는 날짜를 찍게 한다.

**Portfolios 탭의 색은 그 화면이 보여주는 거래일의 마감 방향으로 고정된다.** 시점마다
뒤집으면 넘기는 동안 오늘 오른 종목인지 내린 종목인지가 읽히지 않는다. 다만 숫자 옆
▲▼와 % 색은 그 시점 값을 따라간다(`data-slot-trend`) — 화면 색에 맞춰 뒤집으면
+0.80%에 ▼가 붙는 거짓말이 된다.

**LLM이 없는 사실을 쓰지 못하게 막아뒀다.** 헤드라인에 근거가 없으면 수급 주체나
"차익실현 매물" 같은 표현을 쓰지 못하고, 헤드라인 발행 시각보다 나중 기사로 앞 시점을
설명하지 못한다. 그래도 완전히 없앨 수는 없으니, 판단은 마크다운의 원문 헤드라인과
링크로 확인하는 편이 안전하다.

**API가 실패해도 브리핑은 나간다.** 키가 없거나 라이브러리가 깨지면 규칙 기반
(헤드라인 나열)으로 물러난다. 문구 품질만 떨어지고 파이프라인은 죽지 않는다.

**카드 길이는 글자 수가 아니라 폭으로 맞춘다.** 한글은 약 12.8px, 영문·숫자는 7.6px라
같은 글자 수여도 구성에 따라 넘치거나 남는다. 한글 한 글자를 1.0으로 환산해 폭을
예산으로 쓴다 — 제목 25, 본문 84(28 × 3줄).

**1줄 용량은 계산하지 말고 실측한다.** 폭 ÷ 글자폭으로 구하면 20%씩 어긋난다. 공백을
영문과 같은 0.6으로 세는데 실제 렌더 폭은 3.16px(≈0.27)이라, 공백이 많은 한국어
문장일수록 과대평가된다. 브라우저에서 실제 문구를 재보면 343px 카드에서 제목 27.8 /
본문 30.1이었다(파이썬 가정은 둘 다 25). 예산이 25였을 때는 본문이 2줄로만 차서 카드
아래가 21px 비었다. 값은 가장 좁은 폰(360px 화면 → 카드 328 → 안쪽 304)에 맞춰
내려 잡는다.

**LLM은 상한만 주면 한참 못 미치게 쓴다.** 하한을 예산의 0.85로 줬더니 79%만 채워서,
좁은 폰에서는 3줄이 되지만 넓은 폰(430px)에서는 2줄에 들어가 카드가 비었다. 하한을
0.95로 올리니 평균 88%가 되어 360·375·393·430 어디서도 3줄이 찼고 넘친 카드는 없다.
쓸 재료가 정말 없는 종목(뉴스에 뚜렷한 이유가 없는 날)은 여전히 짧게 나오는데,
자리를 채우려고 없는 사실을 지어내는 것보다 낫다.

**해외 뉴스는 두 소스를 합친다.** yfinance만 쓰면 무관한 기사(NVDA 뉴스에 다른 회사
배당 기사)가 섞여 들어와서, Google News RSS를 함께 보고 종목명·티커가 제목에 없는
기사는 버린다.

**번역·요약은 Claude API를 쓴다.** 무료 구글 웹 번역은 고유명사를 영문으로 남겨서
카드에 영문이 섞인다. 키가 없으면 구글 → 원문 순으로 물러난다.

**폰 폭(≤520px)에서는 축소하지 않고 유동 레이아웃으로 채운다.** 홈 화면에 추가하지
않고 주소만 쳐서 들어와도 앱처럼 보이게 하려는 것이다. 데스크톱에서는 예전처럼
375×812 폰 목업을 통째로 축소해 보여준다.

축소해서 채우는 방법도 있었지만 쓰지 않았다. 가로를 채우려고 확대하면 세로가 모자라
탭바가 화면 밖으로 밀려나고(실측 14% 잘림), 세로를 먼저 맞추면 시안 14px 본문이
12.6px로 줄어든다. 상대 단위로 채우면 14px이 14px로 남는다.

- **가로는 %/calc.** `width:375px` 판들은 `100%`, 카드는 `--card-w:calc(100vw - 32px)`,
  칩 줄은 `calc(100% - 29px)`, 진행 바는 px이 아니라 화면 폭의 24/48/72/95.7%다.
- **세로는 flex.** `top:550px`을 `top:67%`로 바꾸면 화면마다 요소 사이가 제멋대로
  벌어진다. 세로는 비율이 아니라 "고정 높이 머리 + 늘어나는 가운데" 구조여야 한다.
  홈은 원래 `.list-viewport{top:206px;bottom:0}`이라 이미 유동이고, 감춘 상태바 44px만큼
  화면을 끌어올리면 끝난다. Portfolios만 세로 스택을 flex로 바꿨다.
- **`.pf-middle`은 `flex:1 0 auto`에 `max-height`가 걸려 있다.** shrink 0인 이유는
  `min-height`로 최소치를 못박으면 칩·종목명이 몇 줄이 되느냐에 따라 넘쳐서 가격이
  잘리기 때문이다(360×607에서 22px 잘렸다). 모자라면 화면이 스크롤된다.

  `max-height`는 남는 세로를 나눠 받으려고 있다. 홈 화면에 추가하면 브라우저 UI가
  없어 세로가 100~170px 남는데, 이 여유를 한 곳에 몰면 눈에 띈다. 전부 `.pf-stock`이
  먹으면 종목 정보가 71→244로 부풀어 가격 띠(142)·카드(122)가 상대적으로 작아 보이고,
  아예 안 주면 카드 아래에 빈 띠가 생긴다. `.pf-middle` 440으로 천장을 두면
  430×842에서 108px이 가격 띠 아래 꼬리 +77, 카드 아래 +50으로 갈린다.

  **`.pf-stock`만은 여유를 받지 않는다(`flex:0 0 auto`).** 박스가 커지면
  `justify-content:center`가 그 차이를 위아래로 갈라서, 종목명 아래 문구와 가격 띠
  사이가 시안보다 벌어진다 — 박스 110 / 내용 71이면 아래로만 19.5px이 더 붙어
  20.2px이 40px이 됐다. 눈에 보이는 간격은 레이아웃 간격 + line-height 반쪽(3.6px)
  이라 시안 24px = 레이아웃 20.2px이다.
- **JS 상수도 실측으로 바꿨다.** 카드 폭이 화면마다 달라져서 `BRIEF_PITCH=347`,
  `CARD_W=343`을 박아두면 카드가 반쯤 걸친 채 멈추고 스와이프 폭이 어긋난다.
  `briefPitch()` / `rowWidth()`가 레이아웃에서 직접 잰다.
- **`.blob`은 화면보다 넓게 잡는다(`105vw`).** 시안에서는 393px 얼룩이 375px
  프레임보다 넓어서 `blur(50px)`로 흐려진 좌우 끝이 프레임 밖으로 잘려 나간다. 폭을
  고정한 채 화면만 넓어지면 그 끝이 화면 안으로 들어와 사각형 덩어리로 보인다
  (430px 화면에서 좌우 19px씩 틈이 생겼다).
- **`.pf-middle`에는 `padding-bottom:40px`이 있다.** 시안에서 가운데 판은 가격 블록보다
  40px 더 내려가고, 그 꼬리에 진행 컬럼 그라데이션의 끝(#d3e8ff)이 깔린다.
  '시간대별 브리핑' 제목과의 간격도 거기서 나온다. flex로 쌓으면 가격 블록이 마지막
  항목이라 그냥 두면 꼬리가 통째로 사라진다.

**`.pf-stock`의 위아래 여백도 시안에서 옮겨왔다.** 절대좌표일 때는 `top:90px` /
`top:181px`이 알아서 만들어주던 간격이라, 흐름으로 바꾸면 0이 되어 종목명이 가격 띠에
달라붙는다. 칩 줄 바닥 63.5 → 종목명 90이 **26.5**, 종목명 바닥 160.8 → 가격 띠 181이
**20.2**다. 이 값을 넣으면 `.pf-middle`이 시안과 똑같은 363px이 된다.

내용에는 최소 높이가 있다. Portfolios는 상단 116 + 가운데 363 + 제목·카드 152 +
탭바 자리 84 = **734px**이다. 아이폰 15 사파리(393×734)에 딱 맞고, 그보다 짧은 화면에서는
찌그러지는 대신 세로로 스크롤된다. 가격 띠를 142→122로 줄이고 간격을 넓혀도 5px밖에
안 줄어드니, 높이를 벌겠다고 시안 값을 건드릴 이유는 없다.
